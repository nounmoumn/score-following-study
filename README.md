# Score Following · 위치 점프 판단 실험

> 2026.08 – 09 · 개인 연구 · **현재 중단**
> `Python` `NumPy` `librosa` `Matchmaker`

실시간 악보 추적기가 연주 위치를 엉뚱한 곳으로 크게 옮겼을 때, 그 점프를 바로 믿을지 2초 더 지켜볼지를 고르는 분류기를 만들고 검증한 기록입니다.
악보(MIDI) 데이터에서는 효과가 있었지만 실제 오디오 녹음에서는 일반화에 실패했고, 그 실패까지 정리한 뒤 멈췄습니다.

## 출발점

[Gitaru](https://github.com/nounmoumn/gitaru)에서 기타 연주를 따라가는 추적기를 직접 만들었는데, 같은 코드가 반복되는 구간에서 지금 몇 번째 반복인지 헷갈리는 문제가 계속 남았습니다.
곡마다 상수를 손으로 맞추는 방식 말고 다른 접근이 필요해서, 관련 논문(Dannenberg 1984, Dixon 2005 등)부터 읽고 공개 데이터셋으로 문제를 다시 정의했습니다.

## 문제를 ML로 바꾸기

- **샘플**: 추적기가 악보상 2초 이상 위치를 옮긴 순간 하나
- **피처**: 점프 후 2초 동안의 추적 안정성, 다른 추적기와의 위치 일치도, 연주와 두 후보 위치 사이의 크로마 유사도
- **타깃**: 점프를 보류했을 때의 손실 − 바로 따랐을 때의 손실 (정답 위치와의 거리, 상한 있음)
- **모델**: ridge 회귀(NumPy로 직접 구현). 곡마다 점프 수가 달라서 곡별 가중치를 같게 맞췄고, 예측값이 0 이상이면 믿고 아니면 보류합니다.
- **추적기**: [Matchmaker](https://github.com/pymatchmaker/matchmaker)의 OLTW(Arzt)와 HMM 계열 추적기를 고정해서 사용. 추적기 자체는 만들지 않았고, 그 위에 판단기만 얹었습니다.

평가는 결과를 보고 다시 고치지 않도록 이렇게 진행했습니다.

1. 학습용(ASAP MIDI)과 곡·연주자가 겹치지 않는 평가셋(lockbox)을 처음부터 떼어 둠
2. 모델과 판정 기준을 해시로 고정한 뒤 평가셋을 한 번만 열어 봄
3. 오디오(Vienna 4x22) 전이 실험도 판정 기준을 먼저 적어 두고 실행

## 결과

| 실험 | 데이터 | 결과 |
|---|---|---|
| MIDI lockbox | 처음 보는 7곡, 점프 61건 | 판단 정확도: 전부 믿기 71.0% → 분류기 83.4%<br>평균 regret 0.700 → 0.334 (개선폭 95% CI [0.033, 0.824]) |
| 오디오 전이 | Vienna 4x22, 연주 40개 | 같은 조건의 점프가 14건뿐. 한 추적기, 네 곡 중 두 곡에서만 발생. 고정된 MIDI 모델은 오디오 점프를 전부 "믿기"로 판단 |
| 오디오용 단순 규칙 | 미리 정해 둔 연주 32개 | 보류 정밀도 60%, regret이 오히려 0.235 증가 |

그림은 [`paper/figures/`](paper/figures), 요약 수치는 [`results/`](results)의 `result.json` 네 개에 있습니다.

## 배운 것

- MIDI에서 잘 되는 판단 규칙도 오디오로 가면 **그런 상황이 나오는 빈도와 위치부터 달라집니다**. 모델 정확도를 보기 전에, 실제 환경에서 그 상황이 충분히 나오는지(coverage)를 먼저 확인했어야 했습니다.
- "점프 후 잠깐 기다렸다 판단하기"나 "여러 후보를 동시에 유지하기" 같은 아이디어는 이미 선행연구(Arzt & Widmer 2010, Yamamoto et al. 2013 등)에 있습니다. 이 레포의 기여라고 할 만한 건 새 알고리즘이 아니라, 판단 손실 기준의 평가와 도메인 전이 실패 기록입니다.
